## Решение для заявки

Реестр `data/manuals/approved-operations.json` содержит разрешённые формулировки работ. Каждая запись привязана к двигателю, F-коду, узлу, проверенному фрагменту и условиям. `quote` — проверенная выдержка из `reviewed-procedures.json`; `supporting_fragment_ids` связывают продолжение процедуры. Прикладное подтверждение условия F08 — факт механика, а не вывод акустической модели.

Данные для ответа лежат в `data/manuals/conflicts.json`. Ответ должен брать **все** `fragment_ids` нужной темы, а не только наиболее похожую страницу. Эти фрагменты имеют `conflict_only: true`: доступны по точным ID, но не вмешиваются в обычное ранжирование контрольных поисковых запросов.

## Повторная сверка

1. Открыть оригинальные PDF и перейти к указанной порядковой странице. Для ЯМЗ-536 PDF 173 имеет печатный номер 172.
2. Проверить заголовок раздела, диапазон, единицы и условие вместе. Для РК PDF 12 читать именно столбец ЯМЗ-236М2; таблица в PDF повёрнута.
3. Сопоставить `manual_id`, `fragment_id`, `pdf_page`, `applicable_engine_models`, `quote` и строку работы реестра.
4. Проверить на API: неподтверждённое условие F08, страница другого узла и отсутствие операции не вызывают Mock ТОиР; разрешённый F14 проходит до номера заявки после подтверждений.
5. После изменения корпуса выполнить `PYTHONPATH=. python tests/check_manual_search.py artifacts/manual-corpus.json`. Для новых фрагментов дополнительно проверить, что все ID из `conflicts.json` и `approved-operations.json` разрешаются через `verified_fragments()` и применимы к указанному двигателю.

Визуально сверены РЭ ЯМЗ-236 PDF 16, 19, 31, 53; РК PDF 12, 41, 248, 269, 276; РЭ ЯМЗ-536 PDF 173–176; ЗМЗ PDF 107, 143–147. Результаты относятся к выданным версиям руководств, а не к произвольным редакциям.
