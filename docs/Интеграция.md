# Стыки для участников 2–4

## Бэкенд, участник 2

Контракты заказчика использованы напрямую.

| Сервис | Вызов | Ожидаемый ответ |
| --- | --- | --- |
| Mock ML | `POST /diagnose` с `vehicle_id`, `session_id` | 200 и результат с той же парой. Запись проверки из каталога используется как метаданные сессии |
| Mock ТОиР | `POST /tickets` с полями из `TicketRequest` | 201, `status: created`, `ticket_id` |

Интегрированная сборка основана на `feature/mechanic-ui` (`6f3bfb4`). Адаптер `mechanic/team_workflow.py` использует те же `Catalog`, `Workflow`, `Store` и модели, что и маршруты `/api/vehicles/{id}/sessions`, `/api/diagnose`, `/api/diagnosis`, `/api/drafts` и `/api/drafts/{id}/confirm` в командном приложении. Черновик хранит ревизию, а номер восстанавливается из таблицы `submitted_tickets` командного бэкенда. Диалог и журнал хранятся отдельно по той же паре.

Маршруты экрана доступны в [локальном OpenAPI](http://127.0.0.1:8000/api/docs). `TEAM_WORKFLOW_DIR` задаёт путь к локальному бэкенду, `TEAM_DB_PATH` — путь к его SQLite. При появлении рабочего HTTP-стенда `TEAM_API_URL` может проксировать эти же маршруты экрана в согласованный адаптер.

| Маршрут | Вход | Выход |
| --- | --- | --- |
| `GET /api/catalog` | — | `vehicles` со вложенными `sessions`: `session_id`, `checked_at` в ISO 8601. У машины есть `vehicle_id`, `engine_model`, `fuel`, `model`, `make`. Опционально `confidence_threshold` и `fault_types` |
| `GET /api/state` | Query `vehicle_id`, `session_id` | Состояние пары |
| `POST /api/diagnose` | Пара в JSON | Состояние пары с `diagnosis` и `brief` |
| `POST /api/chat` | Пара и `message` | Состояние с сообщениями и, по намерению, с черновиком |
| `PUT /api/draft` | Пара, `edits` и `revision` из `draft_revision` | Состояние с сохранённым черновиком |
| `POST /api/ticket` | Пара, `edits`, `revision` и `priority_confirmed: true` | Состояние с текущим статусом отправки и, при успехе, номером |

Состояние состоит из `diagnosis`, `brief`, `brief_error`, `messages`, `draft`, `draft_revision`, `draft_origin`, `ticket` и `calls`. До первого запроса диагностики `diagnosis`, `brief` и `draft` равны `null`. Черновик содержит весь JSON заявки из OpenAPI ТОиР. К редактируемым полям относятся `conclusion`, `urgency`, `operations`, `spare_parts`. Пара, исходный `anomaly_type` и проверенные ссылки берутся с сервера. Приоритет подтверждается для выбранного значения. Если запчасти не указаны, отправляется `[]`.

В `ticket` передаются `status`, `ticket_id` и `message`. Значения статуса: `idle`, `draft`, `sending`, `created`, `error`, `unknown`. При `sending` экран опрашивает только `GET /api/state`. При ошибке определения статуса появляется кнопка повторной проверки. При `unknown` черновик читается и отправка заблокирована. Mock ТОиР не предоставляет поиск по заявкам, поэтому сверку неопределённого результата должен обеспечить рабочий бэкенд или оператор ТОиР.

Локальное резервирование отправки атомарно проверяет пару в SQLite, фиксирует изменения и только потом вызывает ТОиР. Повтор после `created` возвращает сохранённый номер. Определённый отказ и отсутствие подключения допускают ручную отправку после исправления. Выданные Mock ТОиР номера могут повторяться между процессами заглушки, поскольку она начинает нумерацию заново. Привязка номера к паре хранится у бэкенда.

Ошибки возвращаются в виде `{"error":{"code":"invalid_pair","message":"..."}}`. Для диагностики предусмотрены `ml_unavailable` (503), `ml_timeout` (504), `invalid_pair` (404) и `ml_invalid_response` (502).

## Руководства, участник 3

По умолчанию `backend` и `manual_search` берутся из этого репозитория. `python -m mechanic.prepare` строит `artifacts/manual-corpus.json` из шести PDF штатным `manual_search.corpus`. При другом расположении исходников или индекса задайте `TEAM_MANUALS_DIR` и `TEAM_MANUALS_INDEX`.

Из командного корня с `pdftotext` в PATH:

```powershell
python -m manual_search.corpus <каталог_шести_PDF> <путь_к_manual-corpus.json>
$env:PYTHONPATH='.'
python tests/check_manual_search.py <путь_к_manual-corpus.json>
```

Проверку поиска участника 3 запускает `tests/check_manual_search.py` в командном репозитории с `PYTHONPATH=.` и путём к корпусу. Результат `resolve_source` содержит `manual` и `pdf_page`. Для источника экран открывает `/sources/{slug}/{pdf_page}`; на странице доступны оригинал с `#page=N` и одностраничный PDF, который открывается на нужной странице независимо от поведения якоря. У контрольных страниц есть предварительный просмотр из оригинала.

## Агент и журнал, участник 4

`TEAM_AGENT_URL` подключает агент команды к временному локальному бэкенду. Предлагаемый стык `POST /respond` получает `action: overview | chat`, `vehicle`, `diagnosis`, `message`, `messages`. При активном поиске также передаются `source_candidates`, полученные для текущей модификации из запроса или признаков ML.

- `overview` возвращает `brief` с `risk` (`low`, `medium`, `high`, `unassessed`), `rationale`, `first_check` и источниками.
- `chat` возвращает `reply` с `summary` и `sections`. Раздел содержит `kind` (`signs`, `causes`, `checks`, `work`, `clarify`), `items` и источники. Можно вернуть `draft` с редактируемыми полями и источниками. Черновик привязывается к текущей паре и коду на бэкенде.
- С активным индексом источники передаются как `source_ids` из кандидатов. Сервер разрешает ID с учётом модификации. В режиме без индекса принимаются `references: [{"manual":"236-3902150-Б РЭ","pdf_page":19}]` из каталога документов для указанного двигателя.
- `calls` содержит `tool`, `status`, `duration_ms`, при наличии `model`, `input_tokens`, `output_tokens`. Передавайте каждое обращение к платной модели, включая поиск, переформулировку, черновик и повторы. Журнал экрана не содержит реплик или аудио.

Результат `check_failed` обрабатывается до вызова агента. Противоречие между F08 и бензиновым двигателем требует сверки модификации и записи. Временный порог низкой уверенности — строго ниже 0,60. Качество `warning` показывается независимо от порога. Подтверждение порога и реальных маршрутов остаётся за командой.
