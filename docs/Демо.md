## Живой показ

1. Моторист показывает E549YT198 / S-0011, первую проверку и страницу 19. Вопрос «Можно ли своим ходом перегнать машину до бокса?» показывает, каких измерений не хватает. На странице 53 отдельно видны причины и действия.
2. Показывает подтверждение заявки и восстановление номера после обновления. Для нового номера нужна сессия без отправленной заявки или свежая демонстрационная база.
3. Открывает Y815BM178 / S-0152, спрашивает про шум на средних оборотах, проверяет страницу PDF 107. Затем открывает «Журнал вызовов» этой сессии.
4. Капитан объясняет цепочку Mock ML → поиск с проверкой модификации → черновик → подтверждение → Mock ТОиР. При обсуждении стоимости показывает фактический состав вызовов и тариф, когда они поступят.

## Техническое сравнение

По два парных прогона на каждом кейсе. Старт обоих проходов — готовый результат ML. Финиш — заполненный черновик с проверенными страницами. В прямом проходе скрипт искал текст в оригинале PDF и заполнял поля. В проходе с помощником он задавал вопрос, открывал указанные страницы и создавал черновик. Порядок проходов менялся между повторами.

Это время автоматизированных операций в Chromium. Практический замер моториста с ручным поиском остаётся открытым. Для него один оператор начинает с одинаковой карточки ML, ищет в выданных PDF и останавливает таймер на заполненном черновике. Для второго прохода он использует помощника. В паре сравниваются одинаковые двигатель, отклонение и обязательные поля, порядок двух проходов чередуется.

## Стоимость полного цикла

Токены агента участника 4, подтверждённый тариф и цены дополнительных шагов пока отсутствуют. Локальный дубль использует синтетический парк и не делает вызовов к платной модели. Для рабочего прогона нужно суммировать по всем вызовам `(входные токены × тариф входа + выходные токены × тариф выхода) / 1 000 000` при тарифах за миллион токенов. К сумме добавляются платные шаги вне генерации. На защите укажите модель, валюту и дату тарифа. При разных тарифах считайте объёмы отдельно для каждого тарифа.

## Бонусы

| Возможность | Что можно подтвердить на текущих материалах |
| --- | --- |
| Простой запуск | Реализован запуск стенда и двух заглушек одной командой после установки зависимостей |
| История заявок и график | SQLite хранит отправленную заявку, каталог содержит 3–5 сессий на ТС. Y815BM178 подходит для графика F14 с баллами 0,19, 0,18, 0,63, 0,84. В графике пропуски нужно показывать отдельно от нулей |
| Главный механик | Карточка и приоритет доступны по выбранной сессии. Для сводки по парку нужно подтвердить правила категорий с командой. Уверенность и качество записи влияют на возможность назначить категорию |
| Запчасти | Поле доступно, в подготовленных заявках список пуст. Номера деталей требуют подтверждения применимости к модификации и результату дефектовки |
| Статистика ремонта и простоя | В материалах есть проверки, данных о выполненных ремонтах, ценах и длительности простоя нет. Для показа выбраны ЯМЗ F02 и ЗМЗ F14 по проверяемым источникам |
| Голосовой ввод и языки | Имеет смысл оценить после мобильного прогона. При локализации нужны проверка терминологии, единиц и ссылок на оригинальные страницы |

В ролике показаны синтетические номера и проверки. Для записи использован чистый браузер с вкладкой стенда. Журнал для защиты содержит технические метрики вызовов. [152‑ФЗ, статья 5](https://mintrud.gov.ru/docs/laws/130)
