## Живой показ текущей сборки

1. Открыть `Y815BM178 / S-0152`. Отчёт запускается выбором записи. Показать наблюдение ML, гипотезы причин и различие между признаком стука и установленным дефектом.
2. Спросить: «Стук спереди на средних оборотах. Как различить цепь и гидронатяжитель?». Открыть PDF 107 с причинами и PDF 143 с проверкой стетофонендоскопом. Разборка без уточнения исполнения гидронатяжителя не предлагается.
3. Подготовить черновик. Показать проверенную работу с дословным основанием, предложенный и выбранный приоритет. Проверить заключение, подтвердить приоритет и отправить.
4. Показать фактический `ticket_id`, обновить страницу и сверить сохранённый номер. До подтверждения в ТОиР ничего не отправляется.
5. На живую защиту оставить `O658MX98 / S-0063`: уверенность 0,53, warning. Без отдельного подтверждения предупреждения отправка закрыта; подтверждение приоритета само по себе его не заменяет.

Для основной записи используйте отдельную демонстрационную базу или ещё не отправленную сессию. Существующую рабочую базу удалять не нужно. Режим тестового диалога обозначается на экране; реальную работу модели подтверждает отдельный журнал вызовов.

## Техническое сравнение

**Исторический замер до нового допуска, не повторён на текущей версии.** По два парных прогона на каждом кейсе. Старт обоих проходов — готовый результат ML. Финиш — заполненный черновик с проверенными страницами. В прямом проходе скрипт искал текст в оригинале PDF и заполнял поля. В проходе с помощником он задавал вопрос, открывал указанные страницы и создавал черновик. Порядок проходов менялся между повторами.

| ТС и сессия | Повтор | Прямой поиск в PDF, с | Через помощника, с | Разница, с |
| --- | ---: | ---: | ---: | ---: |
| E549YT198 / S-0011 | 1 | 2,238 | 0,527 | 1,711 |
| E549YT198 / S-0011 | 2 | 1,836 | 0,501 | 1,335 |
| Y815BM178 / S-0152 | 1 | 4,162 | 0,352 | 3,810 |
| Y815BM178 / S-0152 | 2 | 3,970 | 0,372 | 3,598 |
| Среднее | 4 пары | 3,0515 | 0,4380 | 2,6135 |

Это время автоматизированных операций в Chromium. Практический замер моториста с ручным поиском остаётся открытым. Для него один оператор начинает с одинаковой карточки ML, ищет в выданных PDF и останавливает таймер на заполненном черновике. Для второго прохода он использует помощника. В паре сравниваются одинаковые двигатель, отклонение и обязательные поля, порядок двух проходов чередуется.

## Стоимость полного цикла

Исторический локальный замер Gemma 2 2B на MacBook M3 сохранил 3160 входных и 349 выходных токенов на три реплики с черновиком, без отправки ТОиР. Это прежняя логика и один случай; не выдавайте эти объёмы за цену текущего сценария F14. [Исходные замеры](agent/measurements.md) и [журнал](agent/benchmark.json) сохранены.

Для новой версии подготовлен `python -m agent.acceptance_benchmark`, который пишет фактические вызовы в JSON/CSV. В доступной среде Ollama не установлена и порт 11434 недоступен, поэтому новые живые прогоны **не выполнены**. [Статус и команда повторения](agent/acceptance-runs.md). Тестовый UI-ролик без модели не заменяет этот замер.

Формула платного API: сумма по реальным вызовам `(входные токены × тариф входа + выходные токены × тариф выхода) / 1 000 000`, плюс платные операции вне генерации. Для собственного сервера нет токенного счёта API, но есть аренда и сопровождение. [Плановый бюджет и допущения](../README.md#модель-сервер-и-стоимость-эксплуатации).

## Бонусы

| Возможность | Что можно подтвердить на текущих материалах |
| --- | --- |
| Простой запуск | Реализован запуск стенда и двух заглушек одной командой после установки зависимостей |
| История заявок и график | SQLite хранит отправленную заявку, каталог содержит 3–5 сессий на ТС. Y815BM178 подходит для графика F14 с баллами 0,19, 0,18, 0,63, 0,84. В графике пропуски нужно показывать отдельно от нулей |
| Главный механик | Карточка и приоритет доступны по выбранной сессии. По решению брифинга повышенный приоритет назначается тем машинам, у которых поломка будет самой дорогой; значение приоритета выбирает моторист в черновике заявки вручную. Автоматического расчёта категорий по парку нет. Уверенность и качество записи влияют на предупреждения в карточке |
| Запчасти | Поле доступно, в подготовленных заявках список пуст. Номера деталей требуют подтверждения применимости к модификации и результату дефектовки |
| Статистика ремонта и простоя | В материалах есть проверки, данных о выполненных ремонтах, ценах и длительности простоя нет. Для показа выбраны ЯМЗ F02 и ЗМЗ F14 по проверяемым источникам |
| Голосовой ввод и языки | Имеет смысл оценить после мобильного прогона. При локализации нужны проверка терминологии, единиц и ссылок на оригинальные страницы |

Во всех демонстрациях используются синтетические номера и проверки. Для нового ролика сборка, тестовый режим и фактический `ticket_id` зафиксированы в манифесте; исторические замеры не подменяют текущий журнал.
