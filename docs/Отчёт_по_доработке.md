   - в README добавлена ссылка на инструкцию;
   - зафиксированы решения брифинга в `docs/Интеграция.md`, `docs/Приёмка.md`, `docs/Демо.md`: порог 0,60; владелец заявки `unknown` — моторист; повышенный приоритет — для машин с самой дорогой поломкой;

5. **B2 и B3**: новый маршрут `/api/fleet` отдаёт сводку по 50 машинам, категории, историю последних 5 проверок и состояние заявки; в интерфейсе добавлена кнопка «Состояние парка» со спарклайнами, фильтром категорий и переходом «К проверке». Сценарий С4 (главный механик) закрыт. Пороги категорий приняты локально, потому что в ТЗ их нет.
6. **B1 (память по машине)**: `GET /api/history?vehicle_id=...` отдаёт пять последних проверок с номером заявки; экран показывает блок «История проверок этой машины» и обновляет его после отправки и ручной сверки `unknown`.

8. **Инструменты проверки**: `scripts/selftest.py` (весь регресс одной командой), `scripts/cleanroom_check.py` (сборка с нуля из архива заказчика) и `scripts/marathon_monitor.py` (повторные прогоны с журналом).
9. **Регрессионные тесты**: инъекция в описании проверки не создаёт черновик; тесты `/api/fleet`, `/api/history`, офлайн-команд агента и отклонения недоверенного поискового запроса; 25 проверок документации, включая защиту от мозаики в именах и тексте файлов.
