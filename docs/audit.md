Проверены исходное дерево репозитория на `main` (`8a41666`), код построения корпуса и поиска, данные и тесты поставщика, сценарии из ТЗ v6, локальные зависимости и поведение интеграции. Изменения внесены в рабочую копию.

## Проверено

- Все 20 тестов из архива заказчика прошли. Обе ручки `/health` также вызваны у оригинальных приложений через ASGI.
- Все 13 существующих поисковых кейсов прошли. Два диалоговых кейса с оценкой давления и вопросом о перегоне проверены через `/api/chat`.
- Пройдены сценарии бэкенда с тремя исходами диагностики, неправильной парой, HTTP 404/422, тайм-аутом, недоступностью сервиса, валидацией ссылок, конкурентным подтверждением, чтением номера после повторного открытия приложения и сохранением черновика при ошибке доставки.

## Границы проверки и прототипа

- Среда разработки запрещает привязку сокетов к localhost. Запуск Uvicorn был предпринят на 8001 и 8002, а HTTP-маршруты проверены через ASGI-транспорт. Живой запуск трёх процессов и экран фронтенда остаются отдельной проверкой.
- Обработчик чата использует ранжирование фрагментов и цитаты, а для проверенных случаев собирает структурированное объяснение. Подключение LLM и история реплик отсутствуют. Для менее типового вопроса верхний фрагмент может содержать соседние строки или часть многостраничной таблицы. Полнота ответа зависит от индекса. У страниц со сканами требуется OCR или ручная сверка.
- Проверка применимости ссылки выполняется на уровне страницы. Когда на ней есть материалы по нескольким модификациям, точный фрагмент виден в `evidence`. Применимость написанной механиком операции к этой выдержке остаётся предметом его проверки.
- При перезапуске самого Mock ТОиР его память сбрасывается, а нумерация может начаться с `TKT-0001`. Сохранённые ответы остаются в SQLite приложения. Мок не предоставляет API сверки неизвестного результата отправки.
- Настройки рассчитаны на локальный прототип. Аутентификация, разграничение доступа и реальный контур ТОиР в текущей версии отсутствуют.
