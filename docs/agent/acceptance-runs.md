## Автоматические проверки

```bash
python -m pytest tests/test_agent_evidence.py tests/test_manual_agent_answers.py tests/test_agent_drafts.py -q
```

Проверяются все стороны трёх размеченных конфликтов, приоритет фактического замера и вопроса о перегоне над справочным поиском, блокировка F02 без процедуры, общая проверка двигателя, работа адаптера и отсутствие обхода через старый Flask-стенд. Тест Flask пропускается, если эта необязательная зависимость не установлена.

## Два живых прогона

```bash
ollama pull gemma2:2b
ollama serve
# В другом терминале из корня проекта:
python -m agent.acceptance_benchmark --output docs/agent/acceptance-runs.json
```

Нужны подготовленные материалы (`python -m mechanic.prepare`), зависимости проекта и доступная Ollama. Модель и адрес задаются `AGENT_MODEL` и `OLLAMA_HOST_URL`. Прогон использует настоящие вызовы модели и исходные Mock ML / Mock ТОиР через ASGI, отдельную временную SQLite и общий `Workflow`. Промышленная ТОиР не вызывается. Это программная приёмка, а не замер работы механика или физического телефона.

Первый сценарий: `E549YT198 / S-0011`, три вопроса — разбор падения давления, обе нормативные страницы РЭ 19 / РК 12, оценка недостающих данных для перегона. Второй: `Y815BM178 / S-0152`, три вопроса — первая проверка, различение цепи и гидронатяжителя, уточнение проверки — затем проверенный черновик и подтверждение в общем серверном потоке до `ticket_id`.

Рядом с JSON создаётся CSV для калькулятора: одна строка на фактический вызов модели или локальный шаг без LLM. В CSV длительность обращения к LLM — время именно вызова; длительность полного прогона берётся из JSON, а не из суммы модельных задержек. Локальные шаги имеют ноль LLM-токенов. При недоступной модели CSV содержит только заголовок и не изображает выполненный прогон.

JSON хранит начало и окончание каждого прогона, модель, назначение и результат каждого шага, все обращения к LLM, входные и выходные токены и задержку. Суммируются только `steps[].calls`: каждый вызов входит в итог один раз. Локальный поиск и подготовка черновика показаны отдельно от генерации. Если провайдер не вернул счётчик токенов, записывается `null`, а не оценка на глаз. Индексация выполняется до измерения и в эти итоги не входит. Историческая точка сравнения до черновика сохранена в [measurements.md](measurements.md) и [benchmark.json](benchmark.json).
