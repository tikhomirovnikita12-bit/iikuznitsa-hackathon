## Что реализовано и чем проверять

Общее правило, контракт и точные основания описаны в [API допуска](admission-api.md) и [доказательствах](manual-evidence.md). Программные проверки доступны командами:

```bash
python -m pytest tests/test_admission.py tests/test_agent_evidence.py tests/test_backend.py tests/test_chat_history_contract.py -q
PYTHONPATH=. python tests/check_manual_search.py artifacts/manual-corpus.json
```

В тестах используются исходные Mock ML и Mock ТОиР и отдельные временные базы. Прохождение автотестов не заменяет мобильную проверку или качество живой модели. Число прошедших тестов и итог браузерного прогона нужно брать из журнала именно зафиксированной сборки.

## Физический телефон — статус открыт

Физический телефон в доступной среде не подключён. Проверка на нём **не выполнена**. Ширина браузера 390 CSS px проверяет компоновку, но не поведение мобильного PDF-просмотрщика, экранной клавиатуры и реального сенсорного ввода.

1. Подключите компьютер и телефон к одной локальной сети. Запустите `python run.py --host 0.0.0.0 --port 8015`; используйте Python своего виртуального окружения. Для живой модели добавьте `--agent` только при работающей Ollama с установленной моделью. Без этого чат явно остаётся тестовым.
2. Откройте `http://<IP-компьютера>:8015/` в чистом браузере телефона. Запишите модель телефона, ОС, браузер, дату и сборку. При необходимости разрешите приложению доступ в локальной сети настройками устройства.
3. Пройдите F14 до номера. В форме должны читаться работа, цитата, PDF-страница, условия и пояснение приоритета. До подтверждения отправки нет.
4. Проверьте warning без галочки качества, затем с ней; отдельно проверьте низкую уверенность, bad и несовместимый F08. Галочка приоритета не должна подтверждать предупреждение о записи.
5. Откройте оригинал PDF и отдельную страницу. Вернитесь к той же форме: выбранные поля/правки сохраняются, случай не переключается. Сверьте, какие подтверждения восстановились после обычного возврата, и что при изменении результата/версии они сбрасываются.
6. Обновите страницу и сверьте `ticket_id`. Повторите безопасный запрос подтверждения и проверьте отсутствие дубля по журналу API.

Заполняйте факт конкретно: «HTTP 422, код warning_ack_required; `/tickets` = 0», «TKT-… после ack; `/tickets` = 1». При ошибке сохраните телефон/браузер, пару ТС–сессия, шаг, ожидаемое и фактическое поведение.
